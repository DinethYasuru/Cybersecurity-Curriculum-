Gophish, step by step.

A complete, plain-language guide to running an authorised phishing simulation with Gophish — the same tool organisations use to train their own staff. For the lesson deck, open Session 4c · Phishing & Scams.

—What Gophish is

Gophish is a free, open-source phishing-simulation framework. Security teams use it to send a harmless, made-up "phishing" email to their own staff, then measure who opened it, who clicked, and who typed something into a fake login page. The point is never to catch people out — it is to find out, kindly, how ready the team is, and then run short training for whoever needs it.

It is one program. You run it, and it opens a dashboard in your web browser. You don't need to write any code. You build five things — a sending profile, an email template, a landing page, a group of people — tie them together in a campaign, press launch, and watch a live results screen.

In this class

Your "organisation" is the classroom. The sender is the instructor's own test email, the only recipient is the instructor's own test account, and the whole thing runs on the local network. Nobody else is ever a target.

0Before you start: the rules

These come first for a reason. The exact same skill is a paid job or a crime — the only difference is permission.

  • Permission. Only test a system and people you own, or have written authorisation to test.
  • Local only. Classroom machine, local network. Nothing is sent out over the internet.
  • Test accounts only. Use the instructor's own or dummy accounts as both sender and target.
  • Dummy data. Fake names, fake passwords. Never submit anything real.
  • No real brands. Do not clone a real company's login page or imitate a real person or sender.
  • Stop means stop. If anything feels off, pause and ask. Then don't.

1Install & first login

Gophish runs on Windows, macOS and Linux. For the classroom we install it locally on one Windows machine.

  1. Go to getgophish.com and open Download → the GitHub Releases page.
  2. Download the ZIP that matches your computer (for example the 64-bit Windows build).
  3. Extract the ZIP to a folder. You'll see the program file plus a few config files.
  4. Double-click the gophish program to run it. A console window opens and prints two web addresses: an admin address (the dashboard, usually https://127.0.0.1:3333) and a phish address (where test emails point, usually http://0.0.0.0:80).
  5. In that same console, Gophish prints a one-time admin password. Copy it.
  6. Open the admin address in your browser. You'll get a certificate warning because it's a local, self-signed site — that's expected here; choose Advanced → Proceed.
  7. Log in with username admin and the password from the console. Gophish immediately asks you to set a new password. Do it, and keep it safe.

Change the password first

The printed password is temporary and visible to anyone who can see that console. Setting your own password is the first thing you do, before anything else.

Why the certificate warning?

The dashboard uses HTTPS with a certificate the program made for itself, so your browser can't "vouch" for it. On a local machine you own, proceeding is safe. On the public internet you would never click past a warning like this — that warning is one of the phishing red flags from the lesson.

2The dashboard

Down the left side you'll find the pieces you build, roughly in the order you use them:

  • Sending Profiles — the mailbox the test email is sent from.
  • Email Templates — the message people receive.
  • Landing Pages — the page that opens if they click.
  • Users & Groups — who the test goes to.
  • Campaigns — tie it all together and launch.
  • Dashboard — the live results.

We'll build them in that order.

3Sending profile (SMTP)

The mailbox the simulation sends from. In class, this is the instructor's own test email.

Open Sending Profiles → New Profile. A sending profile is just the settings your email program would use to send mail, called SMTP. For a classroom lab you can send through a free test email account you created for this purpose.

NameAnything, e.g. Class test mailbox.
SMTP FromThe test address the email appears to come from — your own test account, never a real person or company.
HostYour test provider's SMTP server and port, e.g. smtp.gmail.com:587.
UsernameYour test account's email address.
PasswordAn app password (see below) — not your normal account password.

App passwords

If your test account has 2-step verification on (it should), your normal password won't work for SMTP. Instead you create a one-off app password in that account's security settings and paste it here. This is a normal, legitimate feature for letting a program send from an account you own. You can delete the app password afterwards.

Use Send Test Email to check it works before going further. A test message should arrive in your own inbox. Then Save profile.

Scope reminder

The "From" address is your own test account. We never configure Gophish to spoof a real company's or person's address — that is out of scope and, outside a signed engagement, illegal.

4Email template

The message people receive.

Open Email Templates → New Template. Give it a name, a subject line, and the body. Gophish lets you write plain text or HTML. For a classroom demo, write a simple, obviously made-up message — for example an internal "please confirm your training account" note from a pretend department.

  • Insert a link that points to your landing page using the placeholder {{.URL}} — Gophish fills in the real address per recipient so it can track clicks.
  • Turn on Add Tracking Image so Gophish can tell when the email is opened.

Keep it fictional

Don't copy a real brand's email, logo or wording. The teaching value is in the shape of a phishing message — urgency, a link, a request — not in imitating a real organisation.

5Landing page

The page that opens if someone clicks the link.

Open Landing Pages → New Page. This is the page a recipient lands on after clicking. For a safe classroom demo, make a simple, neutral page — for example a plain "Training portal" page with a message, or a basic form. Options you'll see:

  • Capture Submitted Data — records that a form was submitted. In class, only ever with made-up data typed by the instructor.
  • Capture Passwords — leave this off for a demo; we are showing the concept of "submitted", not collecting anything.
  • Redirect — after submit, send the visitor to a short "this was a training test — here's what to check next time" page. A real awareness programme does exactly this.

Do not clone a real login page

Gophish has an "Import Site" button that copies a web page. We do not use it to copy a real company's login. Build a plain training page of your own instead. Cloning a real brand to harvest real credentials is the line between a lesson and an attack.

6Users & groups

Who the test goes to.

Open Users & Groups → New Group. Add the recipients: first name, last name, email, position. For a real test this is the list of people who agreed to be tested. For class, add only the instructor's own test address(es).

This is the most important field

A phishing tool is only as ethical as its recipient list. If an address in this group did not agree to be tested, stop. In our lab the group is the instructor's own accounts and nobody else.

7The campaign

Tie it all together and launch.

Open Campaigns → New Campaign and pick the pieces you built:

Namee.g. Class demo.
Email TemplateThe message you wrote.
Landing PageYour training page.
URLThe phish address Gophish printed at startup — on a local lab, your machine's local address. This is what {{.URL}} becomes.
Sending ProfileYour test mailbox.
GroupsYour test-account group.

Press Launch Campaign. The email goes out to the group, and the dashboard starts filling in.

8Reading the results

The numbers that help — they tell you where to teach, not who to blame.

SentIt went out
OpenedThey read it
ClickedThey tapped the link
SubmittedThey typed into the page
Email Sent
The simulation reached the recipient's mailbox.
Email Opened
They opened and read it. Normal and fine.
Clicked Link
They tapped the link and reached the landing page. A gentle reminder is due.
Submitted Data
They typed into the fake page. In a real programme this person gets training first — never blame.
Email Reported
Best outcome: they spotted it and reported it. This is the habit you're building.

The whole point

A good campaign is followed by a two-minute lesson, not a telling-off. That's why we end the class understanding the attacker's view: so that a real "you clicked our test" email feels like help, not a trap.

9To run one for real

An honest list of what an authorised, real-world simulation needs — the first two are the real work.

  1. Written authorisation from whoever owns the people and systems. Without it, everything below is a crime, not a test.
  2. A scope — exactly who is in, what's allowed, and the start and end dates.
  3. A server running Gophish that the test emails come from (a spare laptop or a rented machine).
  4. A mailbox or mail service (SMTP) it is allowed to send through.
  5. An email and a landing page — a believable but fictional message and a harmless page that records a click.
  6. A debrief — report the numbers, then train the people. That is the deliverable.

For this class the "server" is the classroom PC and the "people" are the instructor's own test accounts. That is the whole, legal version of "doing it for real", scaled to one room.

10Out of scope

What we deliberately do not do, and why.

  • Public hosting — no renting a VPS, buying a domain, or sending over the internet.
  • Spoofing — no faking a real company's or person's email address.
  • Real targets — no sending to anyone who hasn't agreed, in writing.
  • Evading defences — no tricks to get past spam filters or security tools.

Some online tutorials show the VPS-and-domain version. We stop at the classroom door on purpose: that part turns a training tool into a weapon, and it is exactly what the Computer Crimes Act covers. We name it so you recognise it, and we leave it out.

11Troubleshooting

The login page won't open / certificate warning

Expected on a local machine — the dashboard's certificate is self-signed. Choose Advanced → Proceed. Make sure you're using the https admin address and port Gophish printed (often 3333), not the phish port.

The test email doesn't send

  • Check the host and port, e.g. smtp.gmail.com:587.
  • Use an app password, not your normal account password.
  • Confirm the test account allows SMTP sending and 2-step verification is set up so an app password can be created.
  • Use Send Test Email and read the error message — it usually names the problem.

Clicks aren't tracked

Make sure the email link uses {{.URL}}, the campaign's URL points at the reachable phish address, and the recipient opened it on the same local network.
